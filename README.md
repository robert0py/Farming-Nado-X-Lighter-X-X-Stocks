# Farming Nado × Lighter × xStocks

Windows-приложение с тёмной панелью управления для подключения аккаунтов Nado и Lighter **на Robinhood Chain** и просмотра реальных балансов. В меню доступны «Баланс» и «Торговля». Сейчас подключено чтение балансов; торговое исполнение будет добавляться отдельными этапами.

## Скачать и подключиться

1. Откройте [последний приватный релиз](https://github.com/robert0py/Farming-Nado-X-Lighter-X-X-Stocks/releases/latest), скачайте `Farming-Accounts.exe` и запустите его. Python устанавливать не нужно. Сборка предназначена для Windows x64.
2. Откройте **«Баланс»**. До подключения показаны статусы «Не подключён» и прочерки. Финансовые значения появляются только после успешного ответа API.
3. **Nado:** нажмите «Подключить», введите публичный адрес кошелька и имя субаккаунта. Обычно это `default`, но укажите имя именно вашего субаккаунта. Нажмите «Показать баланс».
4. **Lighter:** нажмите «Подключить», введите публичный адрес кошелька или индекс аккаунта на Robinhood Chain. Если у кошелька несколько аккаунтов, выберите нужный из списка и нажмите «Показать баланс».

В окне подключения есть ссылка на официальный сайт для входа через ваш кошелёк. Приложение читает публичные данные аккаунта; оно не подтверждает владение кошельком и не создаёт торговую авторизацию. Секретные API-ключи, seed-фраза и приватный ключ для чтения этих балансов не нужны.

После подключения форма закрывается, показываются балансы. Они обновляются автоматически каждые 30 секунд; «Обновить» повторяет запрос вручную. Кнопка «⋯» открывает настройки аккаунта; «Отключить» в этом окне очищает подключение. При ошибке старые значения очищаются, отображается ошибка, а подключённый ранее аккаунт повторно запрашивается по таймеру с учётом ограничений транспорта. Адреса и балансы хранятся только в памяти; после закрытия приложения подключение нужно выполнить снова.

Общая таблица объединяет реальные spot-балансы Nado и балансы токенов Lighter, сохраняя площадку для каждой строки. «События подключения» раскрывает журнал фактических обновлений, ошибок и отключений текущей сессии. Он не сохраняется на диск. Переключение разделов не разрывает подключение аккаунтов.

## Как читать баланс

- **Nado:** показаны spot-токены, включая стейблкоины и отрицательные балансы, если у аккаунта есть долг. Для wrapped xStocks отдельно показан эквивалент xStock по текущему `exchange_rate_x18`. «Стоимость аккаунта» — unweighted health из API, включая влияние существующих позиций и долгов; это не сумма, доступная для вывода.
- **Lighter:** стоимость аккаунта, доступный баланс и обеспечение в USDG. В таблице отдельно приведены баланс токенов, заблокированный баланс и маржинальный баланс. Они не складываются приложением повторно.

Отсутствующий аккаунт отличается от аккаунта с нулевым балансом. На Lighter аккаунт появляется после первого депозита; индекс Lighter Core не относится к Robinhood Chain. Приложение не переключается на другую площадку при ошибке. Раздел «Торговля» прямо показывает, что исполнение ещё не подключено; в нём нет вымышленных ордеров, сделок или истории.

## Разработка

Для исходников нужен Python 3.11+ с Tkinter:

```powershell
python run.py
python -m unittest discover -s tests -v
python run.py --self-check
```

Для Windows-сборки (проверено с Python 3.13):

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
./scripts/build-windows.ps1 -Python .venv\Scripts\python.exe
```

Сборка создаёт `dist/Farming-Accounts.exe` и `dist/SHA256SUMS.txt`, затем проверяет запуск упакованного приложения. Runtime не использует сторонних Python-зависимостей. PyInstaller нужен только для сборки.

Код коммитится и отправляется в приватный репозиторий после каждого завершённого изменения. После каждого push кода в `main` GitHub Actions запускает проверки, собирает `.exe` и публикует новый **приватный** релиз. Доступ к релизам имеет тот же круг пользователей, что и к репозиторию. Серверный деплой ещё не настроен; эта версия работает локально.

Подключения отделены от интерфейса в `src/farming_accounts/accounts.py`. Сетевой транспорт разрешает только четыре HTTPS GET-маршрута для чтения и запрещает перенаправления. Он не содержит методов подписи, ордеров, переводов или вывода средств. Таймауты, один повтор временного сбоя и задержка после ограничения запросов не блокируют интерфейс.
