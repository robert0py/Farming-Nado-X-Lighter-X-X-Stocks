# Farming Nado × Lighter × xStocks

Windows-приложение с тёмной панелью «Баланс» и «Торговля» и отдельным торговым worker. Версия **0.3.0** добавляет настройку торгового доступа и циклического хеджа: покупка разрешённых spot xStocks на Nado и противоположная позиция на том же базовом активе в Lighter **на Robinhood Chain**.

Интерфейс показывает данные API и сохранённый журнал фактических операций. В продукте нет вымышленных балансов, сделок или демонстрационного исполнения. Торговый код работает с реальными API; на пополненных пользовательских аккаунтах исполнение пока не проверялось. Проверки без ордеров и автоматические тесты не заменяют такую проверку.

## Скачать и подключиться

1. Откройте [последний приватный релиз](https://github.com/robert0py/Farming-Nado-X-Lighter-X-X-Stocks/releases/latest), скачайте `Farming-Accounts.exe` и запустите его. Python устанавливать не нужно; сборка предназначена для Windows x64. Контрольная сумма находится в `SHA256SUMS.txt`.
2. Для просмотра балансов откройте **«Баланс»**. Укажите публичный адрес кошелька Nado и имя субаккаунта, затем адрес или индекс аккаунта Lighter Robinhood Chain. Это публичное чтение, не торговая авторизация; ключи и подпись кошелька не нужны.
3. Для торговли откройте **«Торговля» → «Этот ПК»**. Приложение подключит отдельный локальный worker. Для удалённого worker используйте **«Подключить VPS»**, его HTTPS-адрес и отдельный токен управления.
4. На каждой площадке нажмите **«Настроить ключ»**: сохраните существующий отдельный signing key либо создайте новый и подтвердите привязку своим браузерным кошельком. Основной приватный ключ и seed-фраза боту не передаются. Затем нажмите **«Проверить доступ»**.
5. В настройках стратегии выберите как минимум два разрешённых базовых актива, размер каждой стороны и ограничения риска. Подтвердите по действующей программе участие выбранного аккаунта Nado и выбранных активов в xPoints. Это подтверждение пользователя, а не автоматическая проверка начисления points.
6. Нажмите **«Проверить без ордеров»**. После успешной проверки отдельная кнопка **«Запустить реальные циклы»** разрешает отправку настоящих ордеров. Сохранение настроек и запуск worker сами по себе торговлю не включают.

Подключения в разделе «Баланс» живут в памяти текущего окна; суммы обновляются каждые 30 секунд и по кнопке. При ошибке устаревшие значения очищаются. Торговые ключи и настройки worker сохраняет зашифрованно: Windows DPAPI текущего пользователя, Linux AES-GCM с отдельным файлом master key. Журнал циклов и ордеров находится в SQLite; он содержит приватные сведения об операциях, но не signing keys.

## Как работает торговля

Nado открывает только **spot xStocks** из подтверждённого пользователем списка. Кредитное spot-плечо отключено; перед покупкой проверяются средства, комиссии и лимит размера без заимствования. Lighter использует только Robinhood Chain. Размер противоположной позиции учитывает wrapper rate Nado, единицы инструментов и ограничения точности обеих площадок.

Открытие spot Nado использует ограниченный по цене FOK; Lighter и закрытие обеих сторон — ограниченные по цене IOC. Частичное исполнение, отказ второй стороны и неизвестный результат обрабатываются отдельно. Intent сохраняется до отправки ордера; при неопределённости worker сверяет состояние с площадкой и не повторяет запись вслепую. Пока остаточная экспозиция не разрешена, новый цикл не начинается.

Стандартное удержание — **12 часов после фактического формирования обеих сторон**. Затем worker закрывает хедж и выбирает другой подходящий разрешённый актив. Циклы продолжаются до команды остановки либо срабатывания ограничений риска и исполнения. Доступность рынков, правила, стаканы и wrapper rate проверяются повторно. При отсутствии подходящего рынка worker ждёт. Участие в программе xPoints подтверждено пользователем для сохранённого аккаунта и списка активов; автоматической гарантии eligibility или начисления points нет.

**«Остановить новые циклы»** запрещает следующие открытия; текущий хедж завершится по таймеру. **«Закрыть хедж и остановить»** запрашивает контролируемое закрытие обеих сторон. Закрытие окна приложения не останавливает независимый worker. Выключение компьютера останавливает локальный worker; работа при выключенном ПК требует VPS. **Сервер пока не развёрнут.**

Полная инструкция по ключам, стратегии и ограничениям: [docs/TRADING.md](docs/TRADING.md). Подготовленный запуск на Linux VPS без Docker: [docs/SERVER.md](docs/SERVER.md).

## Балансы и ограничения

- Nado показывает реальные spot-балансы, включая долг, если он уже есть; для wrapped xStocks — эквивалент по `exchange_rate_x18`. Стоимость аккаунта из health API не равна сумме, доступной для вывода. Торговый worker блокирует операции при выявленном spot-долге.
- Lighter показывает стоимость, доступный баланс и обеспечение в USDG. Аккаунт Robinhood Chain должен существовать; индекс аккаунта Lighter Core не подходит.
- Signing keys имеют полномочия самой площадки, которые могут быть шире ордеров. Бот не содержит методов вывода, перевода или депозита; это не ограничивает права украденного ключа на стороне площадки.
- Оценка PnL и лимита убытка не включает funding и изменение курса USDT0/USDG; подробные границы расчёта приведены в инструкции. Хедж не гарантирует отсутствие убытка или получение points.

## Разработка

Проверяемая сборка использует Python **3.13**. Для desktop из исходников нужен Tkinter; headless worker его не импортирует.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-runtime.txt
.venv\Scripts\python.exe run.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe run.py --self-check
```

Независимый локальный worker из исходников:

```powershell
.venv\Scripts\python.exe run.py --worker
```

Runtime-зависимости фиксируются в `requirements-runtime.txt`: официальный `lighter-sdk`, `eth-account` и `cryptography`. Nado использует документированные HTTP/WebSocket API и EIP-712 через `eth-account`; старый Nado SDK с несовместимыми требованиями к `eth-account` в общий runtime не устанавливается. Обновление SDK требует повторной проверки Robinhood Chain, native signer и схем API, а не снятия фиксации версии.

Windows-сборка:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
./scripts/build-windows.ps1 -Python .venv\Scripts\python.exe
```

Сборка создаёт `dist/Farming-Accounts.exe` и `dist/SHA256SUMS.txt` и проверяет запуск упакованного приложения. После завершённого изменения код коммитится и отправляется в приватный репозиторий; GitHub Actions проверяет код и публикует приватный desktop release. Серверный деплой выполняется после появления настроенного VPS; сейчас назначения для него нет.

Исследование API: [docs/API_RESEARCH.md](docs/API_RESEARCH.md). Текущее состояние и следующие этапы: [docs/ROADMAP.md](docs/ROADMAP.md). Примечания версии: [docs/RELEASE_NOTES.md](docs/RELEASE_NOTES.md).
