# Farming Nado × Lighter × xStocks

Windows-приложение с тёмной панелью «Баланс» и «Торговля» и отдельным торговым worker. Версия **0.5.6** фиксирует новые позиции на **1×**: Lighter подтверждает настройку до открытия первой стороны, Nado проверяет полное обеспечение фьючерсной экспозиции. Размер позиции не умножается. «Учёт» сохраняет семь показателей: количество закрытых хеджей, объёмы Nado и Lighter, общий объём, общие комиссии, суммарный PnL и общие затраты. История загружается автоматически через API за выбранные даты. Для открытия и закрытия Nado по-прежнему применяются maker-лимитки; Lighter хеджируется и сокращается по подтверждённым исполнениям Nado. Обновление не запускает новые циклы.

Интерфейс показывает данные API и сохранённый журнал фактических операций. В продукте нет вымышленных балансов, сделок или демонстрационного исполнения. Торговый код работает с реальными API; на пополненных пользовательских аккаунтах исполнение пока не проверялось. Проверки без ордеров и автоматические тесты не заменяют такую проверку.

## Скачать и подключиться

1. Откройте [последний приватный релиз](https://github.com/robert0py/Farming-Nado-X-Lighter-X-X-Stocks/releases/latest), скачайте `Farming-Accounts.exe` и запустите его. Python устанавливать не нужно; сборка предназначена для Windows x64. Контрольная сумма находится в `SHA256SUMS.txt`.
2. Для просмотра балансов откройте **«Баланс»**. Укажите публичный адрес кошелька Nado и имя субаккаунта, затем адрес или индекс аккаунта Lighter Robinhood Chain. Это публичное чтение, не торговая авторизация; ключи и подпись кошелька не нужны.
3. Для торговли откройте **«Торговля» → «Этот ПК»**. Приложение подключит отдельный локальный worker. Для удалённого worker используйте **«Подключить VPS»**, его HTTPS-адрес и отдельный токен управления.
4. Нажмите **«Настроить ключ»**. Для Nado создайте отдельный signer через **MetaMask**. Для Lighter по умолчанию выбрано **Robinhood Wallet · API-ключ с сайта Lighter**: откройте официальную страницу API Keys кнопкой в форме, создайте ключ через Robinhood Wallet и вставьте его вместе с индексами. Основной приватный ключ и seed-фраза боту не передаются. Затем нажмите **«Проверить доступ»**. Пошаговая инструкция: [docs/KEY_SETUP.md](docs/KEY_SETUP.md).
5. В настройках стратегии выберите как минимум два разрешённых базовых актива, размер стороны Nado и время удержания. Доступны топ-5 общих крипторынков по объёму Lighter RH и SPY/QQQ. Режим «Ближе к исполнению · maker» выбирает ближайший шаг строго ниже ask для покупки или выше bid для продажи; проверка цены по умолчанию через 90 секунд. Доступен и процентный отступ от середины стакана. Сохранённые настройки не заменяются автоматически. Обычный хедж не зависит от xPoints; получение поинтов не гарантируется.
6. Нажмите **«Проверить без ордеров»**. После успешной проверки отдельная кнопка **«Запустить реальные циклы»** разрешает отправку настоящих ордеров. Сохранение настроек и запуск worker сами по себе торговлю не включают.

Подключения в разделе «Баланс» живут в памяти текущего окна; суммы обновляются каждые 30 секунд и по кнопке. При ошибке устаревшие значения очищаются. Торговые ключи и настройки worker сохраняет зашифрованно: Windows DPAPI текущего пользователя, Linux AES-GCM с отдельным файлом master key. Журнал циклов и ордеров находится в SQLite; он содержит приватные сведения об операциях, но не signing keys.

## Как работает торговля

Плечо новых циклов — **1× на обеих площадках**. Указанная сумма — полный размер позиции, а не маржа, которую бот умножает на плечо. Lighter сохраняет настройку по рынку и по умолчанию может использовать 2×; теперь бот заранее устанавливает cross 1× и подтверждает через аккаунт `initial_margin_fraction=100.00` (100%, signer использует 10000 bps). До подтверждения первый ордер Nado не отправляется. Перед открывающим ордером Lighter настройка читается снова. Nado работает в cross: отдельного параметра плеча в ордер не добавляется; полная стоимость новой плюс существующей фьючерсной экспозиции проверяется по собственным USDT0 и equity. Спотовый заём по-прежнему запрещён. Более высокое плечо пока отклоняется; отдельные `nado_leverage` / `lighter_leverage` в стратегии подготовлены для последующего расширения. 1× не превращает perpetual в spot и не отменяет funding или движения стоимости обеспечения.

Настройка Lighter 1× выполняется только на пустом рынке без ордеров, с записью намерения до отправки. ACK не считается подтверждением; после неизвестной отправки или перезапуска читается настройка без повторного POST. Существующие позиции и закрывающие ордера не перенастраиваются. Для применения этой версии нужен worker 0.5.6: активный старый worker автоматически не подменяется, прежний хедж нужно завершить перед его обновлением. Сохранённые старые ордера остаются доступны для сверки и закрытия.

Для криптовалют используются perpetual на обеих площадках с возможностью чередовать направления после завершённого цикла. Для SPY/QQQ Nado покупает только spot xStocks, без спотового займа, Lighter открывает встречный perpetual. Lighter использует только Robinhood Chain. Размер противоположной позиции учитывает wrapper rate Nado, единицы контрактов и ограничения точности обеих площадок.

Основная стратегия использует maker post-only на Nado и ограниченный по цене IOC на Lighter. Цена maker-покупки — на **выбранный процент ниже середины свежего стакана Nado** (по умолчанию 0,02%) ((bid + ask) / 2), с округлением вниз по шагу цены. Первая заявка отправляется после обязательных проверок без ожидания интервала перестановки; ответы API могут занять время. Отсчёт начинается после отправки заявки. Через выбранное время ожидания (по умолчанию 90 секунд) бот проверяет расстояние до этой текущей рыночной цены: при расстоянии **не больше выбранного процента** сохраняет заявку и её очередь; при большем расстоянии после доказанной отмены пересчитывает цену в той же попытке открытия. Если округление даёт прежнюю цену, перестановки нет. После указанного времени ожидания проверка повторяется при каждой сверке, без обязательной отмены по таймеру. Количество пересчитывается в пределах бюджета покупки; заявка сохраняет maker post-only. Частичное исполнение запрашивает отмену остатка и хеджирование подтверждённой покупки. Ожидание заявки не считается открытым или завершённым хеджем. Окно показывает реальный статус, количество, цену и ID ордера. Частичное исполнение, отказ второй стороны и неизвестный результат обрабатываются отдельно. Intent сохраняется до отправки ордера и отмены; при неопределённости worker сверяет состояние с площадкой и не повторяет запись вслепую. Пока остаточная экспозиция не разрешена, новый цикл не начинается. Непосредственно в форме достаточно выбрать активы, сумму покупки и время; защита рассчитана автоматически, дополнительные поля можно раскрыть.

Стандартное удержание — **12 часов после фактического формирования обеих сторон**. Затем worker закрывает хедж и выбирает другой подходящий разрешённый актив. Циклы продолжаются до команды остановки либо срабатывания ограничений риска и исполнения. Доступность рынков, правила, стаканы и wrapper rate проверяются повторно. При отсутствии подходящего рынка worker ждёт. Участие в программе xPoints подтверждено пользователем для сохранённого аккаунта и списка активов; автоматической гарантии eligibility или начисления points нет.

**«Остановить новые циклы»** запрещает следующие открытия; текущий хедж завершится по таймеру. **«Закрыть хедж и остановить»** запрашивает контролируемое закрытие обеих сторон. Закрытие окна приложения не останавливает независимый worker. Выключение компьютера останавливает локальный worker; работа при выключенном ПК требует VPS. **Сервер пока не развёрнут.**

Полная инструкция по ключам, стратегии и ограничениям: [docs/TRADING.md](docs/TRADING.md). Подготовленный запуск на Linux VPS без Docker: [docs/SERVER.md](docs/SERVER.md).

## Балансы и ограничения

### Учёт и выгрузка истории

Справа только семь показателей: **количество закрытых хеджей**, **объём Nado**, **объём Lighter**, **суммарный объём**, **потрачено на комиссии**, **суммарный PnL**, **общие затраты**. Объём — покупки плюс продажи по фактическим ценам за весь период, без прибавления комиссий и без повторного учёта частичных распределений. Комиссии суммируются по обеим площадкам, PnL — сумма реализованного PnL Nado и Lighter по всем сделкам за период, включая сделки без пары. **Общие затраты = комиссии − суммарный PnL**: убыток увеличивает затраты, прибыль уменьшает; отрицательная сумма означает чистую прибыль. Отсутствующий PnL или комиссия дают прочерк соответствующего полного итога. Прочерк Closed PnL у явно обозначенного открытия Lighter означает нулевой реализованный PnL, у закрытия — неизвестный. Спотовый PnL Nado не подменяется нулём. Закрытые хеджи считаются при полном закрытии суммарной сопоставленной позиции актива внутри периода, частичные исполнения не увеличивают счётчик. Общие показатели сохраняются в `Totals.csv` и `Report.json`; `Summary.csv` сохраняет детализацию по площадкам. Суммарные показатели в USD — оценка по курсу USDT0/USDG 1:1, funding не включён. Методика остаётся в выгрузке, без поясняющих абзацев справа.

В разделе **«Баланс» → «Учёт»** выберите даты в местном времени, включая последний день, и нажмите **«Загрузить по API»**. Приложение получает все рынки выбранного cross-субаккаунта Nado и выбранного аккаунта Lighter **Robinhood Chain**, включая ручные сделки. Для Lighter используется сохранённый отдельный API-ключ из раздела «Торговля». Для локального отчёта не нужно останавливать или обновлять уже работающий торговый процесс. При подключении к VPS история читается на сервере через защищённые маршруты `/accounting/*`; сервер должен поддерживать версию 0.5.3 или новее. Серверные ключи на компьютер не передаются.

**«Скачать ZIP»** сохраняет `Nado.csv`, `Lighter.csv`, `Hedge-report.csv`, `Closed-hedges.csv`, `Summary.csv`, `Report.json` и пояснения. Отдельная кнопка **«CSV парами»** сохраняет только объединённую таблицу. В паре сначала Nado, затем Lighter. Частичные исполнения распределяются по количеству без удвоения комиссий; строки без пары остаются в конце. Исходные таблицы нормализованы и содержат полные исполнения до распределения, а не сырые подписанные ответы API. Ключи, подписи и временные ссылки выгрузок в отчёт не попадают. `Report.json` удобен для анализа в ChatGPT.

Сопоставление **предполагаемое**: одинаковый базовый актив, противоположная сторона и ближайшее исполнение в пределах пяти минут. Оно не доказывает принадлежность ручных сделок к одному циклу. Для xStocks без исторического коэффициента обмена обёртки пара не назначается, текущий курс в старые сделки не подставляется. Неактивные неизвестные рынки остаются в истории с ID продукта. CSV Lighter предоставляет Trade ID, но не Order ID; эти идентификаторы не подменяются друг другом.

Комиссии и сообщённый площадкой реализованный PnL показаны отдельно в **USDT0** и **USDG**. Оценка закрытых хеджей сопоставляет противоположные пары FIFO внутри периода, считает изменение цен обеих сторон и вычитает четыре распределённые комиссии. Совокупная оценка предполагает курс USDT0/USDG **1:1**, не включает funding, газ кошелька, проценты по споту и переоценку открытых остатков. Если открытие было до выбранного периода или комиссия неизвестна, полный результат такого хеджа не рассчитывается. Отсутствующее значение — пустая ячейка, не ноль.

`gap_seconds` показывает разницу времени исполнений (Lighter минус Nado). Разница цен включает базис рынков; её **нельзя выдать за убыток от задержки** без исторической цены Lighter в момент исполнения Nado. Эта отдельная сумма остаётся неизвестной. Время исходного CSV Lighter имеет точность до секунды; CSV/JSON используют UTC, экран — местное время.

Один отчёт ограничен 366 днями, 50 000 исходных исполнений и 32 МБ выгрузки Lighter; большие периоды нужно разбить. Пагинация Nado включает перекрытие границ, чтобы не потерять частичные исполнения. При неполной странице, неизвестном формате или ошибке одной площадки сводка не выдаётся за полный отчёт. Загрузку можно отменить независимо от торговли. Готовый отчёт хранится в памяти до следующей загрузки/закрытия окна; серверная сессия скачивания истекает через 30 минут без обращения. Сохранённые пользователем отчёты содержат приватную торговую историю.

API: [Nado Matches](https://docs.nado.xyz/developer-resources/api/archive-indexer/matches), [Lighter export](https://apidocs.lighter.xyz/reference/export). Схема Lighter подтверждена на `api.rh.lighter.xyz`; Core API не используется.

- Nado показывает реальные spot-балансы, включая долг, если он уже есть; для wrapped xStocks — эквивалент по `exchange_rate_x18`. Стоимость аккаунта из health API не равна сумме, доступной для вывода. Торговый worker блокирует операции при выявленном spot-долге.
- Lighter показывает стоимость, доступный баланс и обеспечение в USDG. Аккаунт Robinhood Chain должен существовать; индекс аккаунта Lighter Core не подходит.
- Signing keys имеют полномочия самой площадки, которые могут быть шире ордеров. Бот не содержит методов вывода, перевода или депозита; это не ограничивает права украденного ключа на стороне площадки.
- Оценка PnL и лимита убытка не включает funding и изменение курса USDT0/USDG; подробные границы расчёта приведены в инструкции. Хедж не гарантирует отсутствие убытка или получение points.

## Разработка

Проверяемая сборка использует Python **3.13**. Для desktop из исходников нужен Tkinter; headless worker его не импортирует.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-runtime.txt
.venv\Scripts\python.exe run.py
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe run.py --self-check
```

Независимый локальный worker из исходников:

```powershell
.venv\Scripts\python.exe run.py --worker
```

Runtime-зависимости фиксируются в `requirements-runtime.txt`: официальный `lighter-sdk`, `eth-account` и `cryptography`. Nado использует документированные HTTP/WebSocket API и EIP-712 через `eth-account`; старый Nado SDK с несовместимыми требованиями к `eth-account` в общий runtime не устанавливается. Обновление SDK требует повторной проверки Robinhood Chain, native signer и схем API, а не снятия фиксации версии.

Windows-сборка:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
./scripts/build-windows.ps1 -Python .venv\Scripts\python.exe
```

Сборка создаёт `dist/Farming-Accounts.exe` и `dist/SHA256SUMS.txt` и проверяет запуск упакованного приложения. После завершённого изменения код коммитится и отправляется в приватный репозиторий; GitHub Actions проверяет код и публикует приватный desktop release. Серверный деплой выполняется после появления настроенного VPS; сейчас назначения для него нет.

Исследование API: [docs/API_RESEARCH.md](docs/API_RESEARCH.md). Текущее состояние и следующие этапы: [docs/ROADMAP.md](docs/ROADMAP.md). Примечания версии: [docs/RELEASE_NOTES.md](docs/RELEASE_NOTES.md).

Временные ошибки чтения API (таймауты, потеря соединения, HTTP 429/5xx) и устаревшие цены переводят текущую попытку в ожидание API. Задача сохраняется и после восстановления связи продолжает сверку того же ордера. Неисполненные и истёкшие maker-заявки не завершают цикл и не расходуют лимит корректирующих сделок; общего тайм-аута 10 или 20 минут на покупку нет. Неподтверждённые записи не повторяются. Неверный ключ, противоречивые позиции и действительные ограничения риска по-прежнему останавливают исполнение.
