# Версия 0.4.0

- Исправлено скрытое устаревшее подтверждение Nado: несовпадение linked signer теперь снимает зелёный статус и показывает способ восстановления. Кнопка «Перепривязать ключ Nado» готовит привязку существующего ключа, не генерируя замену; владелец подтверждает подпись в MetaMask.
- Основные настройки — активы, сумма покупки и время удержания. Защита рассчитывается автоматически; дополнительные поля доступны через «Настроить защиту вручную». Старые настройки меняются только после сохранения новой формы, автоматического запуска нет.
- Nado использует maker post-only на лучшей пассивной цене. Через 20 секунд ожидания остаток отменяется отдельной операцией с постоянным журналом до отправки. Lighter хеджирует только подтверждённое исполнение после завершения ордера Nado. Потерянный ответ отмены не вызывает повторную запись.
- Подтверждённая отмена без исполнения сверяется с фактическим балансом; частичное исполнение дополнительно сверяется с архивом, ценой и комиссиями. После перезапуска восстанавливаются сохранённые digest и операции отмены. Три отменённых без исполнения maker-закрытия останавливают автоматическое исполнение с сохранением остатка; рыночного переключения Nado нет.
- Малые существующие spot-остатки сохраняются отдельно от покупок бота. Значительные позиции и внешние ордера по-прежнему запрещают новый цикл. Недостаточная сумма после округления теперь показывает вычисленный минимум, не увеличивая бюджет пользователя.
- Проверены чтение и авторизация Lighter Robinhood Chain с сохранённым ключом; реальные ордера при разработке не отправлялись. Несовпадающую привязку Nado нужно восстановить одной подписью владельца перед реальной торговлей.

# Версия 0.3.4

- Активы стратегии выбираются галочками из общих рынков Nado spot xStocks и Lighter Robinhood Chain. Названия, ID, минимумы и ограничения открытия берутся из актуального API; ручной ввод тикеров убран.
- Публичное чтение рынков не требует уже сохранённой стратегии или signer-ключей и не блокирует торговый движок. Парсеры метаданных общие для выбора и исполнения; ограничения разрешённых активов торгового адаптера сохранены.
- В форме объяснено чередование разных активов между циклами и хедж одного базового актива на обеих биржах. Поля переименованы, проскальзывание вводится в процентах, рядом есть подсказки «!» с поддержкой клавиатуры.
- Прокручиваемая форма сохраняет видимую кнопку сохранения; ошибки отображаются рядом. При сбое обновления нельзя сохранить устаревшие рынки, после смены списка требуется подтверждение xPoints. Финансовые значения не подставляются автоматически.
- Пройдены 199 тестов, включая соответствие рынков, закрытые сессии и запреты открытия, публичный GET без ключей, проценты и порядок активов, ошибки обновления и минимальную сумму, доступность сохранения при высоком DPI. Реальные ордера при проверке не отправлялись.

# Версия 0.3.3

- Подключение Lighter через Robinhood Wallet теперь по умолчанию использует отдельный API-ключ с официального сайта. В форме есть инструкция, переход прямо на API Keys, копирование адреса сайта и закреплённая кнопка «Сохранить ключ».
- Nado подключается через MetaMask. Для Lighter способ создания ключа в боте через MetaMask остаётся отдельным вариантом. Мобильный Robinhood Wallet не отображается как расширение браузера; на странице бота есть переход к правильному способу подключения.
- Ручной импорт ключа аннулирует предыдущую ссылку привязки для этой площадки. Отмена восстановления старого ключа сохраняется одновременно с новым ключом, чтобы перезапуск не вернул старую привязку.
- Проверено 186 автоматических тестов; официальный сайт Lighter проверен до подписания и создания ключа. Реальные сделки и регистрация пользовательского ключа не выполнялись. Множитель 2× для API-сделок не подтверждён; пояснение добавлено в интерфейс и инструкцию.

## Исправления 0.3.2

- Исправлено создание ключа Lighter с пустыми индексами: аккаунт и свободный API key index определяются по публичному адресу через API Robinhood Chain. Если аккаунтов несколько, пользователь выбирает нужный из полученного списка.
- Адрес и индекс аккаунта подставляются из подтверждённого баланса. Новый ключ не заменяет занятый индекс; занятость повторно проверяется перед генерацией.
- Нажатие кнопки во время обновления состояния дожидается его завершения и выполняет запрос один раз. Подготовка показывает индикатор ожидания и сообщения об ошибках в форме.
- Проверен 181 автоматический тест, чтение публичного API и подготовка сообщения регистрации официальным SDK без отправки транзакции. Настоящая подпись владельца и регистрация пользовательского ключа при проверке не выполнялись.

## Исправления 0.3.1

- Исправлены формы ключей Nado и Lighter: два понятных способа подключения, закреплённая кнопка сохранения, Enter и ошибки непосредственно в форме. Содержимое прокручивается при небольшом окне или повышенном масштабе Windows.
- Привязка через браузер разделена на проверку адреса, подключение выбранного EVM-кошелька и отдельную подпись. Добавлены обнаружение кошельков EIP-6963, смена разрешённого аккаунта, инструкции для MetaMask и проверка сети Nado.
- Ссылка привязки сохраняется при перезагрузке страницы и может быть скопирована в другой браузер. После отправки подписи повторная регистрация блокируется; неопределённый результат сверяется через восстановление в приложении.
- При подключении новой версии desktop остановленный локальный процесс предыдущей версии обновляется штатно. Активная стратегия и незавершённый хедж не прерываются автоматически.

## Возможности, добавленные в 0.3.0

Windows x64 · Hedge Bot · Nado spot xStocks / Lighter Robinhood Chain.

- Раздел «Торговля»: подключение независимого локального worker или HTTPS worker на VPS, настройка доступа, стратегии, просмотр состояния хеджа, таймера, остаточной экспозиции и истории циклов.
- Отдельные signing keys Nado и Lighter: ввод существующего ключа либо создание в worker с подтверждением привязки браузерным кошельком. Основной приватный ключ не запрашивается. Неопределённый результат регистрации можно сверить без повторной отправки регистрации.
- Зашифрованное хранение ключей и настроек: Windows DPAPI / Linux AES-GCM. Durable SQLite journal сохраняет intent до отправки ордера и позволяет сверять результат после перезапуска. Один worker владеет журналом.
- Проверка без ордеров проверяет аккаунты, ключи, доступные рынки, соответствие активов, размеры, ликвидность и ограничения исполнения. Торговля начинается только отдельной командой «Запустить реальные циклы».
- Открытие spot Nado — FOK без заимствования; противоположная позиция Lighter и закрытие обеих сторон — IOC с ограничением цены. Обработаны частичные исполнения, неизвестный результат и запрет новых циклов при неразрешённой экспозиции.
- Удержание по умолчанию 12 часов после формирования хеджа, затем закрытие и выбор другого разрешённого актива. Раздельные команды остановки новых циклов и контролируемого закрытия текущего хеджа.
- Участие аккаунта и активов в xPoints подтверждает пользователь. Это подтверждение сохраняется для выбранного аккаунта и списка активов; начисление points автоматически не проверяется. Рыночная доступность и ограничения читаются из API.
- Подготовлены Linux systemd service и инструкция установки с TLS, отдельным master key и резервным копированием. VPS пока не развёрнут: локальный worker требует включённого компьютера.
- Существующий раздел «Баланс» продолжает читать публичные реальные балансы без ключей; в интерфейсе нет вымышленных сумм, ордеров или истории.

Торговое исполнение на пополненных пользовательских аккаунтах **ещё не проверялось**. Выполнены автоматические проверки и чтение публичных API; реальные средства, пользовательские signing keys и funded trading при разработке не использовались. Оценка PnL не включает funding и курс USDT0/USDG; хедж не гарантирует отсутствия убытка или получение points.

Скачайте `Farming-Accounts.exe`; Python для Windows-релиза устанавливать не нужно. `SHA256SUMS.txt` содержит контрольную сумму. Инструкции: [торговля](TRADING.md), [сервер](SERVER.md).
