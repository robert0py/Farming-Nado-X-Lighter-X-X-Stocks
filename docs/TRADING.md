# Торговля и подключение отдельных ключей

Торговый движок открывает покупку **spot xStock на Nado** и противоположный short соответствующего **perpetual на Lighter Robinhood Chain**. Nado perpetual, продажа spot в долг и Lighter Core не используются. Размер хеджа рассчитывается в единицах базовой акции: количество wrapped-токенов Nado умножается на актуальный `exchange_rate`; одинаковое число токенов на площадках не означает одинаковую экспозицию.

В продукте нет демонстрационных балансов и сделок. Проверка подключения читает реальные API. Реальная отправка ордеров начинается после команды запуска пользователя. Автоматический цикл, авторизация и восстановление проверяются изолированными тестами; сделки на пополненных аккаунтах пользователя ещё не проводились.

## Где работает торговля

Desktop показывает состояние и отправляет команды отдельному worker. На Windows кнопка подключения локального worker запускает независимый фоновый процесс на `http://127.0.0.1:8765`. Закрытие окна desktop не останавливает его. Выключение компьютера, сон Windows или завершение процесса останавливают локальное исполнение. При последующем запуске worker сверяет сохранённые ордера и позиции, а не начинает новый хедж вслепую.

VPS пока не настроен. Для работы при выключенном компьютере требуется развернуть worker на постоянно работающем сервере, настроить его автозапуск, persistent state directory, защищённое хранилище и HTTPS. Desktop подключается к серверу с отдельным токеном управления. Внешний HTTP без TLS запрещён; HTTP доступен только через loopback этого компьютера.

Запуск из исходников после установки зависимостей:

```powershell
python -m pip install -r requirements-runtime.txt
python run.py --worker
```

Дополнительные параметры worker доступны через `python run.py --worker --help`. Для удалённого управления предусмотрены `--host`, `--certificate`, `--certificate-key`, `--public-url`. Сам факт наличия этих параметров не означает, что сервер уже развёрнут. Обновления кода сохраняются в приватном репозитории и публикуются как Windows-релизы; автоматический серверный деплой настраивается после выбора сервера.

## Последовательность подключения

1. Открыть «Торговля» и подключить worker.
2. Настроить оба аккаунта: Nado и Lighter Robinhood Chain. Можно сохранить уже зарегистрированный отдельный торговый ключ или создать и привязать новый через браузерный кошелёк.
3. Для Nado выбрать «MetaMask · создать отдельный signer», открыть браузер, подключить нужный адрес и отдельно подписать привязку. Для Lighter по умолчанию выбран «Robinhood Wallet · API-ключ с сайта Lighter»: кнопка открывает официальный раздел API Keys, где нужно войти через Robinhood Wallet, создать отдельный ключ и скопировать его вместе с двумя индексами в форму бота. Нажать «Сохранить ключ» или Enter, затем «Проверить доступ». Дополнительный способ создания ключа Lighter в боте через MetaMask позволяет оставить индексы пустыми для поиска по публичному адресу. Основной приватный ключ и seed-фраза не нужны. Полная инструкция: [KEY_SETUP.md](KEY_SETUP.md).
4. Сохранить разрешённые активы, размер одной стороны и ограничения риска. Для смены актива между циклами нужны как минимум два подходящих базовых актива. Стандартное удержание — 12 часов от фактического формирования обеих сторон.
5. Проверить действующую программу xPoints, участие аккаунта и каждого выбранного xStock. Подтверждение относится к конкретному адресу и субаккаунту Nado.
6. Выполнить проверку без ордеров: авторизация, рынки, торговые ограничения, единицы, ликвидность, баланс/маржа, размеры и журнал незавершённых операций.
7. Запустить реальную стратегию отдельной командой. Проверка подключения сама не открывает позиции.

### Если браузерный кошелёк не подключается

Подключение кошелька к сайту площадки не разрешает доступ локальной странице бота: разрешения действуют отдельно для каждого origin. Откройте страницу в браузере, где установлено расширение кошелька. Если браузер по умолчанию другой, скопируйте полную ссылку из формы приложения и вставьте в нужный браузер. Ссылка содержит одноразовую сессию после `#`; не публикуйте её и не удаляйте эту часть. Она действует пять минут; после истечения создайте новую в приложении.

На странице выберите нужное расширение, разблокируйте его и нажмите «Подключить кошелёк». Ожидаемый адрес показан в шаге 01, разрешённые адреса — в шаге 02. При несовпадении нажмите «Выбрать другой аккаунт» и разрешите доступ нужному адресу. Если MetaMask сообщает об ожидающем запросе, откройте расширение и подтвердите либо отклоните этот запрос. Затем повторите подключение. Не вводите основной приватный ключ или seed-фразу в приложение.

Для Nado сеть берётся из подписываемого запроса API. Для известных сетей Ink и Ink Sepolia кошелёк предложит добавить сеть, если её нет. Неизвестная сеть не подменяется другой. Lighter подписывает сообщение регистрации; переключение EVM-сети для этой подписи не требуется. При отклонённой подписи можно повторить запрос подписи. После отправки подписи на сервер повторная отправка отключена: если результат неизвестен, используйте «Восстановить привязку ключа» в приложении.

Desktop обновляет предыдущий локальный worker только после штатной остановки и при отсутствии активной стратегии или незавершённого хеджа. Проверка журнала выполняется самим worker. Если обновление заблокировано незавершённым циклом, завершите его в предыдущей версии; принудительное завершение процесса не закрывает позиции.

Источники реализации: [MetaMask Provider API](https://docs.metamask.io/metamask-connect/evm/reference/provider-api/), [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963), [официальный пример MetaMask](https://github.com/MetaMask/vite-vanilla-ts-eip-6963), [сети Ink](https://docs.inkonchain.com/general/network-information).

### Nado

Нужны публичный адрес владельца, имя субаккаунта и приватный ключ **отдельного linked signer**. Обычно имя основного субаккаунта — `default`. До привязки субаккаунт должен существовать и иметь не менее 5 USDT0 стоимости аккаунта.

Новая привязка создаёт signer в worker и готовит EIP-712 `LinkSigner` для подписи основным кошельком в браузере. `sender` всегда содержит адрес владельца и имя его субаккаунта; `signer` содержит публичный адрес отдельного ключа. Chain ID и endpoint-контракт читаются из текущего `contracts` API. Нельзя копировать chain ID из примеров документации: публичная проверка mainnet 9 октября 2026 вернула Ink `57073`, но код читает актуальный ответ перед регистрацией.

Программа проверяет подпись владельца, nonce и параметры сети до отправки привязки, затем сверяет текущий `linked_signer`. Для дальнейших ордеров используется только отдельный ключ. Основной ключ в поля приложения не вводится.

**Linked signer имеет полные права на соответствующий субаккаунт, включая вывод; это не ключ с гарантированно ограниченными торговыми правами.** Бот предоставляет только разрешённые торговые операции, но компрометация ключа позволяет использовать более широкие права площадки. Выделяйте для бота отдельный субаккаунт с контролируемой суммой средств.

На один субаккаунт приходится один linked signer. Новая привязка заменяет прежний, отменяет все его resting-ордера и может нарушить работу существующего Nado «1-Click Trading». Лимит — 50 привязок за 7 дней на субаккаунт. Документация описывает генерацию браузерного ключа для 1-Click Trading, но не документирует его экспорт; приложение не требует извлекать такой ключ из браузера.

Источники: [Linked Signers](https://docs.nado.xyz/developer-resources/get-started/linked-signers), [Link Signer](https://docs.nado.xyz/developer-resources/api/gateway/executes/link-signer), [Signing](https://docs.nado.xyz/developer-resources/api/gateway/signing), [Contracts](https://docs.nado.xyz/developer-resources/api/gateway/queries/contracts).

### Lighter Robinhood Chain

Нужны публичный адрес кошелька, существующий account index в инстанции Robinhood Chain, отдельный API key index и API private key Lighter. Публичное чтение баланса по адресу не заменяет авторизацию для торговли. Если аккаунта ещё нет, сначала требуется создать и пополнить его на официальной площадке.

Для нового ключа worker генерирует отдельную пару и готовит регистрацию, которую владелец подтверждает в браузерном кошельке. Используйте свободный API key index: `4–156` или `158–254`; зарезервированные индексы не используются. При вводе существующего ключа программа сверяет аккаунт, адрес, индекс и зарегистрированный публичный ключ через API.

API-ключ Lighter также может иметь более широкие полномочия, чем открытие ордеров. Не считайте отсутствие кнопки вывода в боте ограничением прав самого ключа. В интеграции используется только `https://api.rh.lighter.xyz` и signing chain ID `466324`; L1 chain ID Robinhood `4663` и Lighter Core не подставляются вместо них.

Источники: [Get Started](https://apidocs.rh.lighter.xyz/docs/get-started), [API Keys](https://apidocs.rh.lighter.xyz/docs/api-keys), [Account Types](https://apidocs.rh.lighter.xyz/docs/account-types), [Rate Limits](https://apidocs.rh.lighter.xyz/docs/rate-limits), [Robinhood Lighter Domains](https://docs.robinhood.com/chain/lighter-domains/).

## xPoints и доступные пары

Перед открытием нужен одновременно доступный spot xStock Nado и perpetual Lighter на ту же базовую акцию. Движок читает текущие статусы, price/size increments, minimum notional, wrapper rate, часы рынка и стаканы. Закрытый или неподходящий рынок не заменяется другим инструментом ради расписания. Когда пары нет, worker ждёт.

Наличие `exchange_rate_x18` подтверждает wrapper xStocks в Nado, но не подтверждает начисление xPoints конкретному аккаунту. Универсального API, доказывающего участие каждого аккаунта и токена в текущей программе, интеграция не предполагает. Пользователь подтверждает сведения по официальной программе и списку активов; отметка в приложении сохраняет это подтверждение, а не выдаёт независимую гарантию начисления.

Подтверждение сохраняется для указанного аккаунта и списка активов. Циклы продолжаются до команды остановки или ограничения стратегии; таймер ежедневного ручного подтверждения отсутствует. При изменении выбранных активов или аккаунта требуется соответствующее подтверждение участия. Доступность рынков проверяется автоматически; участие в программе и её изменения пользователь проверяет по официальным правилам.

Источники: [xPoints on Nado](https://docs.nado.xyz/incentives-and-rewards/xpoints-on-nado), [xStocks Spot Trading](https://docs.nado.xyz/developer-resources/api/xstocks-spot-trading), [V2 Symbols](https://docs.nado.xyz/developer-resources/api/v2/symbols), [Wrapped xStocks](https://docs.xstocks.fi/developers/wrapped-xstocks), [xStocks Points](https://defi.xstocks.fi/points).

## Исполнение и остановка

Открытие Nado использует ограниченный по цене **FOK**: покупка должна исполниться целиком или отмениться. Это предотвращает намеренное создание spot-остатка меньше минимального размера. Lighter и закрытие обеих сторон используют ограниченные по цене **IOC**: возможны частичные исполнения. Закрытие short Lighter и продажа spot Nado — reduce-only. Во всех Nado spot-записях передаётся `spot_leverage=false`; площадка должна отклонить операцию, создающую заём. Дополнительно проверяются имеющийся spot, положительный quote-баланс, комиссии и `max_order_size` без leverage.

Подтверждение отправки не равно исполнению. Ордер сохраняется до записи; движок использует постоянные client IDs и nonce, фактические cumulative fills и комиссии. У Nado идентификатором служит подписанный digest: необязательный API `id` в digest не входит. Пустая история или отсутствие ордера в стакане не доказывают нулевое исполнение.

Потоки Nado подключаются до отправки. Неполные события, разрыв связи или расхождение с фактическим spot-балансом переводят операцию в сверку. Если авторизация потока для конкретного delegated signer не подтверждена, адаптер останавливается до отправки ордера. После перезапуска используются сохранённый intent, архив исполнений и актуальные позиции. Неизвестная запись не повторяется вслепую.

Резерв маржи, предел проскальзывания, допустимая остаточная экспозиция и время непокрытой стороны задаются пользователем. Лимит убытка контролирует оценку стоимости закрытия доступного хеджа; это не полный отчёт о прибыли. Funding, FX USDG/USDT0, проценты и все особенности корпоративных действий не включены в такую оценку. Подтверждённые комиссии ордеров сохраняются отдельно; они также не превращают оценку в гарантированную чистую прибыль.

«Остановить новые циклы» запрещает следующие открытия и позволяет текущему хеджу завершиться по таймеру. «Закрыть и остановить» запрашивает контролируемое закрытие обеих сторон. Не нажимайте принудительное завершение процесса вместо команды закрытия: прекращение программы не закрывает позиции на площадках.

Источники исполнения: [Nado Place Order](https://docs.nado.xyz/developer-resources/api/gateway/executes/place-order), [Max Order Size](https://docs.nado.xyz/developer-resources/api/gateway/queries/max-order-size), [Order Events](https://docs.nado.xyz/developer-resources/api/subscriptions/events), [Historical Orders](https://docs.nado.xyz/developer-resources/api/archive-indexer/orders), [Endpoints](https://docs.nado.xyz/developer-resources/api/endpoints).

## Секреты и проверка

Worker обрабатывает состояние с интервалом 10 секунд и учитывает время ответов API. Лимит времени без хеджа должен быть больше 10 секунд; его превышение вызывает попытку контролируемого закрытия. Этот лимит не гарантирует время фактического закрытия при недоступной площадке или отсутствии ликвидности.

Ключи и токен управления не отправляйте в чат, GitHub, логи и снимки экрана. Windows хранит секреты через DPAPI текущего пользователя; на Linux используется зашифрованный vault и защищённый master key file. Перенос на другой сервер требует отдельной настройки хранилища, а не копирования всего рабочего каталога в Git.

Сетевые запросы торгового адаптера Lighter проходят через `aiohttp` с проверкой TLS и используют настроенный на компьютере системный/environment proxy, если он есть. Разрешены только конкретные операции на `https://api.rh.lighter.xyz`; автоматические redirects отключены, чтобы auth-токены и подписанные запросы не пересылались на другой адрес. Auth-токены обновляются каждые 10 минут; торговые POST не повторяются автоматически.

Зафиксированный официальный `lighter-sdk==1.1.6` требует `urllib3<2.1.0`, поэтому установка зависимостей выбирает `urllib3==2.0.7` с известными последующими security advisories. В нашей интеграции `urllib3` используется SDK для служебного форматирования HTTP-заголовков, а его сетевой путь через `requests` (синхронный nonce manager) не вызывается: nonce читается через асинхронный API. Это ограничение зависимости сохраняется и не означает отсутствия риска во всём пакете. Для обновления нужен совместимый выпуск SDK либо отдельно проверенное изменение его dependency metadata; текущая сборка не подменяет ограничения официального пакета. [Объявления безопасности urllib3](https://github.com/urllib3/urllib3/security/advisories), [зависимости официального SDK](https://github.com/elliottech/lighter-python/blob/main/setup.py).

Проверены публичные API рынков, account readers, подпись и восстановление в изолированных тестах. Тесты охватывают частичные исполнения, неизвестный результат записи, смену wrapper rate, несовпадение signer, защиту от займа, restart, сохранение таймеров и остановку. Факт прохождения этих проверок не является подтверждением исполнения сделки на аккаунте пользователя: его ключи и пополненные торговые аккаунты ещё не предоставлены программе.
