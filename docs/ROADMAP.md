# Состояние проекта и следующие этапы

Обновление направления 16.10.2026, версия 0.5.0: добавлен hedge crypto-perpetual Nado ↔ Lighter Robinhood Chain с maker Nado, market IOC Lighter и чередованием сторон. Из xStocks для нового выбора оставлены SPY/QQQ только с покупкой spot Nado. Фарминг xStocks вынесен пользователем в отдельную будущую задачу; обычная торговля не зависит от подтверждения xPoints. Предыдущие требования ниже сохранены как история и контекст, не обещание поинтов. Новые криптоордера в ходе разработки на пополненных аккаунтах не отправлялись.

Проект развивается как рабочее приложение по функциональным этапам. Финансовые значения поступают из API; синтетические данные используются только в изолированных тестах. Версия 0.3.0 содержит публичный просмотр балансов, торговую панель, отдельный worker, настройку signing keys и механизмы исполнения хеджа. Реальная торговля на пополненных пользовательских аккаунтах пока не проверена, VPS не развёрнут.

## Реализовано

- Версия 0.5.3: «Баланс» → «Учёт», автоматическая история по API за период, попарные исполнения, частичные распределения, комиссии и оценка закрытых хеджей, CSV/ZIP/JSON. История читается отдельно от активного торгового процесса; серверные ключи при удалённом чтении не передаются на desktop. Пары и общий результат по курсу котировок 1:1 являются явно отмеченными оценками. Изолированная маржа, funding и точное причинное отделение задержки от базиса не входят в этот отчёт.

- Windows desktop с разделами «Баланс» и «Торговля». Публичное чтение Nado и Lighter Robinhood Chain не требует signing keys; торговый доступ настраивается отдельно.
- Независимый worker, который сохраняет ключи зашифрованно, принимает аутентифицированные команды desktop и ведёт durable journal. Локальный процесс переживает закрытие окна, но требует включённого ПК. Подготовлены TLS-запуск и systemd service для Linux.
- Привязка отдельного Nado signer и Lighter API key через браузерный кошелёк без передачи основного приватного ключа. Проверка зарегистрированного ключа и восстановление неопределённого результата регистрации чтением API.
- Проверка аккаунтов, совместимых инструментов, текущих правил рынка, ликвидности, wrapper rate, шага количества/цены и доступных средств до ордеров. Отдельный явный запуск настоящего исполнения.
- Сохранение intent до сетевой записи, контроль двух сторон, частичных исполнений, неизвестных результатов, остаточной экспозиции и сверки после перезапуска. Неопределённая запись не повторяется вслепую; новый цикл блокируется до reconciliation.
- Повторяющиеся циклы с удержанием 12 часов по умолчанию и сменой разрешённого базового актива после закрытия. Отдельные команды «Остановить новые циклы» и «Закрыть хедж и остановить».
- Ограничения проскальзывания, остаточной экспозиции, времени без полного хеджа, резерва средств и оценки убытка. Ограничения оценки PnL указаны в [TRADING.md](TRADING.md).

## Постоянные требования стратегии

Nado покупает **только spot xStocks**, для которых пользователь проверил участие своего аккаунта и выбранных активов в действующей программе xPoints. Признак wrapped xStock сам по себе не является доказательством eligibility. Подтверждение сохраняется для конкретного аккаунта и выбранного списка; автоматического источника, гарантирующего points для каждого аккаунта и токена, не установлено. Правила программы следует перепроверять при их изменении.

Nado perpetual и кредитное spot-плечо не используются. Lighter работает только на Robinhood Chain и открывает противоположную экспозицию на тот же базовый актив. Размер учитывает wrapper/exchange rate, единицы и точность обеих площадок. Одинаковое число токенов не означает одинаковую экспозицию.

Пользователь задаёт размер, допустимые активы и срок удержания. Таймер отсчитывается после фактического формирования двух сторон. После закрытия worker выбирает другой подходящий разрешённый актив и повторяет цикл до остановки либо срабатывания ограничений. Когда подходящего рынка нет, он ждёт; не заменяет разрешённые активы случайными инструментами и не открывает непокрытую позицию ради расписания.

## Следующие этапы

1. Проверить реальное исполнение на выбранных пользователем аккаунтах после их настройки: подпись, исполнение FOK/IOC, комиссии, частичное закрытие, фактическая сверка и восстановление. Автоматические тесты не доказывают эти свойства на пополненном аккаунте.
2. Развернуть worker на выбранном Linux VPS: TLS и DNS, защищённый master key, доступ desktop, резервные копии и проверка перезапуска. Только после этого торговля сможет продолжаться при выключенном пользовательском ПК.
3. Подключить доставку последующих серверных обновлений на настроенное назначение, с сохранением журнала и проверкой восстановления. Сейчас серверных credentials и назначения нет.
4. Расширять наблюдение и подтверждение eligibility по официальным источникам, когда появится подходящий источник данных; не считать наличие API или wrapper rate гарантией начисления points.
5. Добавить Telegram отдельным последующим этапом по запросу пользователя.

## Сохранение и доставка

Каждое завершённое изменение кода коммитится и отправляется в приватный репозиторий. Windows-код проходит тесты, сборку и публикацию в приватном GitHub Releases. После настройки серверного деплоя последующие завершённые серверные изменения также разворачиваются там. Signing keys, основной приватный ключ, seed-фразы, токены управления, настройки аккаунтов, реальные балансы и журналы в Git не попадают.
